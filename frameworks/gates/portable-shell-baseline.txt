# THIS IS A DEBT LEDGER, NOT AN EXEMPTION MECHANISM. Two properties make it shrink rather than
# accumulate:
#   1. A finding NOT listed here is a hard failure. New unportable spellings cannot land.
#   2. A line listed here that NO LONGER TRIPS is ALSO a hard failure ("stale baseline entry").
#      So fixing a site forces deleting its line in the same PR — the ledger cannot silently
#      outlive the debt and quietly re-exempt the same defect in the same file years later.
# Property 2 is the half that is usually missing, and the half that does the work: without it an
# "exemption list" only ever grows, and a fixed defect keeps a standing invitation to come back.
#
# FORMAT: <repo-relative path>@@<the rule's full "why" text, verbatim>

# accepted, because that file is already on the ledger and slated for a fix. That is why the 2
